# وثيقة التسليم للمرحلة التالية (Handoff Document — Phase 2 to Phase 3)

> **مرحباً بك أيها الوكيل 3 (Agent 3):**
> هذه الوثيقة هي **أول ملف يجب أن تقرأه**. اكتملت المرحلة الثانية بنجاح تام، وتم تفعيل كافة الميزات الحية: فحص السرعة الفعلي، خريطة نقاط التوزيع بـ Leaflet، مشغل HLS، استراحة الوسائط المحلية، وطبقة البيانات المزدوجة.

## 1) الحالة الراهنة للمشروع بعد اكتمال المرحلة 2

- **الحزمة التقنية:** Next.js 15 App Router + React 19 + TypeScript الصارم + Tailwind CSS 4 + Motion + Vitest.
- **جودة الكود:**
  - `npm run build` ينجح بنسبة 100% بدون أي أخطاء.
  - `npm run lint` ينجح بنسبة 100% مع 0 أخطاء.
  - `npm run typecheck` ينجح بنسبة 100% (`tsc --noEmit`).
  - `npm test` ينجح بنسبة 100% (11 اختبار وحدة للدوال الرياضية والاحصائية).
- **الهوية البصرية المعتمدة:** نظام «مدار» بالهوية الملكية والشبكية (DEC-007 وDEC-008): الذهبي الملكي (`#C59424`) والأزرق الشبكي السيان (`#0284C7`) مع خلفيات دافئة `#F8F8F7` وخطوط محلية Readex Pro و IBM Plex Sans Arabic. صفحة المعاينة الحية: `/design`.
- **ترويسات الأمان و PWA:**
  - `vercel.json` مهيأ بـ `Permissions-Policy: camera=(self), microphone=(), geolocation=(self)` (الكاميرا مفتوحة مسبقاً لمسح QR في المرحلة 3).
  - سياسة CSP متكاملة تدعم Cloudflare و OpenStreetMap و Supabase ومشغلات الوسائط.
  - Service Worker `public/sw.js` بالنسخة `talqanet-cache-v2` مع كاش مخصص لبلاطات خريطة مأرب وتجاوز دقيق لفحص السرعة.

## 2) ما يعمل حالياً بالتفصيل (What Works 100%)

1. **فحص السرعة الفعلي الشامل (`SpeedTestView` / `/speed` / `SpeedTestModal`):**
   - محرك قياس حقيقي `SpeedTestRunner` بدون أي أرقام مصطنعة:
     - **Ping & Jitter:** 10 طلبات صغيرة مع استبعاد إحماء الاتصال وحساب الوسيط والتذبذب.
     - **Download Throughput:** اتصالات متوازية عبر قراءة تدفق البايتات في الوقت الفعلي مع نافذة تسخين 1.5 ثانية وحساب متوسط مقطوع Trimmed Mean بالميجابت/ثانية (Mbps).
     - **Upload Throughput:** رفع كتل بيانات متوازية وقياس السرعة الفعلية.
   - **مزودان للخدمة (Dual Providers):** خوادم Cloudflare Global Edge كمزود رئيسي، وخوادم Route Handlers داخل التطبيق (`/api/speed/down` و`/api/speed/up`) كمزود احتياطي.
   - عداد حي 60fps ومراحل تفاعلية مع دعم الإلغاء الفوري (`AbortController`).
   - تنبيه استهلاك بيانات الهاتف (Cellular Warning) مع فحص Network Information API.
   - مشاركة النتيجة عبر Web Share API والنسخ للحافظة.
   - سجل آخر 10 فحوصات محلياً مع رسم بياني مصغر Sparkline وتغذية حلقة الإشارة في الصفحة الرئيسية.
2. **الاستراحة والتنزيلات المحلية (`LoungeView` / `/lounge`):**
   - بطاقات مغذاة من طبقة البيانات لسيرفر الأفلام Jellyfin (`http://192.168.50.2:8096`).
   - تحميلات سريعة لملفات الألعاب والتطبيقات (`talqa-net.apk`, `pubg-update.zip`, `freefire.apk`) بأحجامها الحقيقية.
   - روابط تنقل علوية آمنة وإشعار صادق («تعمل داخل شبكة طلقة فقط»).
   - لعبة تحدي الذاكرة تعمل بسلاسة بدون إنترنت.
3. **بث المباريات المشغل المباشر HLS (`MatchesView` / `/live`):**
   - مشغل `HlsVideoPlayer` المعتمد على `hls.js` مع التشغيل الأصلي على Safari/iOS.
   - أزرار التحكم: تشغيل/إيقاف، كتم وتحكم بالصوت، ملء الشاشة، Picture-in-Picture، وتبديل مستويات الجودة، وزر إعادة المحاولة.
   - دمج Screen Wake Lock API لمنع انطفاء الشاشة أثناء مشاهدة المباراة.
   - القنوات مستوردة من طبقة البيانات مع زرع القنوات الثلاث (`bein1`, `bein2`, `ssc1`) بحالة `enabled: false` لحين اعتماد مصادر البث المرخصة من صاحب الشبكة (خالية تماماً من النتائج أو المعلقين الوهميين).
4. **الباقات ونقاط التوزيع وخريطة مأرب (`PackagesView` / `/packages`):**
   - خريطة جغرافية تفاعلية بـ Leaflet و OpenStreetMap بدون مفتاح API، مع علامات مخصصة ذهبية وشبكية ونوافذ معلومات واتجاهات.
   - قائمة نقاط التوزيع مع ساعات العمل المهيكلة وحساب حالة الفتح والإغلاق الحالية وحساب المسافة التقديرية بالكيلومتر عبر Geolocation بإذن صريح.
   - ورقة تفاصيل لكل فئة كرت (Bottom Sheet) مع خطوات الاستخدام ونقاط البيع الخاصة بكل كرت وزر طلب واتساب المباشر.
   - الإبقاء على شارة «بيانات أولية» لنقاط التوزيع لحين اعتماد صاحب المشروع.
5. **طبقة البيانات المزدوجة (`src/lib/data/repository.ts`):**
   - واجهة `ContentRepository` بتنفيذين:
     - `StaticSeedRepository`: يعمل افتراضياً كخيار صفري الإعداد (Zero-Config) مع كاش `localStorage` بنمط Stale-While-Revalidate، ولا يعرض شاشة بيضاء أبداً.
     - `SupabaseRepository`: يتفعل تلقائياً فور توفر `NEXT_PUBLIC_SUPABASE_URL` و`NEXT_PUBLIC_SUPABASE_ANON_KEY`.
   - ملف الترحيل وسياسات الأمان: `supabase/migrations/0001_content_tables.sql` مع أمان RLS صارم (قراءة عامة للمحتوى المنشور، ولا كتابة مجهولة).

## 3) ما يجب على الوكيل 3 فعله أولاً (Action Plan for Agent 3)

1. **الخطوة الأولى — ربط Firebase Cloud Firestore & Auth (DEC-014):**
   - تم اعتماد مشروع Firebase الرسمي الخاص بالشبكة (`talqanet-cf3e1` بـ Cloud Firestore على خطة Spark المجانية).
   - إعداد ملف الاتصال `src/lib/firebase/config.ts` بمفاتيح البيئة (`NEXT_PUBLIC_FIREBASE_API_KEY`, `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN`, `NEXT_PUBLIC_FIREBASE_PROJECT_ID`, إلخ).
   - بناء مزود البيانات `FirestoreRepository` بـ `src/lib/data/repository.ts` ليتصل بمجموعات Firestore:
     - `packages` (باقات الكروت والأسعار).
     - `distributors` (نقاط التوزيع وإحداثيات مأرب).
     - `announcements` (الإعلانات والتنبيهات).
     - `channels` (قنوات البث).
     - `lounge_items` (عناصر الاستراحة والتنزيلات).
     - `app_settings` (إعدادات التطبيق وروابط الدعم).
   - الحفاظ على `StaticSeedRepository` كطبقة سقوط أوفلاين دائمة لضمان عدم توقف التطبيق عند انقطاع الإنترنت.

2. **الخطوة الثانية — مسابقة الانتماء (Loyalty System) على Firestore:**
   - تطبيق المعاملات الذرية `runTransaction()` في Firestore لمنع ظاهرة التنافس (Race conditions) ومطابقة المنطق الذري القديم:
     - مجموعة `consumed_vouchers`: وثائق بأسماء أكواد الكروت (`voucherCode`) لمنع إعادة استهلاك الكرت نفسه مرتين.
     - مجموعة `reward_vault`: رصيد الكروت الرابحة الجاهزة للسحب بفئاتها.
     - مجموعة `reward_claims`: سجل الفائزين وتفاصيل الجوائز وتاريخ السحب.
   - بناء واجهة إدخال الكروت الـ 10 التفاعلية في `/rewards` مع مدقق صيغة الكرت، ومسح رمز الاستجابة السريعة (QR Scanner) مستفيداً من إذن الكاميرا `camera=(self)`.
   - ربط عجلة الحظ (Lucky Wheel) بفيزياء الدوران المعتمدة لتستقر على الجائزة الناتجة من السيرفر.

3. **الخطوة الثالثة — لوحة الإدارة المصغّرة (Admin Dashboard):**
   - حماية لوحة الإدارة بـ Firebase Auth أو رمز PIN آمن مع قواعد أمان Firestore (`firestore.rules`).
   - واجهة لإدارة الباقات والأسعار والإعلانات ونقاط التوزيع.
   - مراقبة وشحن صندوق جوائز مسابقة الولاء (إضافة كروت رابحة جديدة).
   - استعراض الكروت المستهلكة وسجل الفائزين.

4. **الخطوة الرابعة — التنظيف والإنهاء:**
   - حذف مجلد `legacy/` والمجلدات غير المستعملة بعد استخراج منطق المسابقة لتسليم مستودع نقي.
   - فحص وتأكيد قياسات Lighthouse للأجهزة الذكية واختبار بناء التطبيق نهائياً.

## 4) المشاكل المعمارية والقيود المعروفة

1. **المحتوى المختلط (Mixed Content):**
   - عناوين الشبكة المحلية (`http://192.168.50.2:*` و`http://t.net`) تعمل بـ HTTP وتفتح حصرياً عبر روابط تنقل خارجية بـ `target="_blank"`. لا تحاول عمل `fetch()` من المتصفح إلى HTTP من نطاق HTTPS للإنتاج. الحل المستقبلي المقترح لصاحب الشبكة هو وضع خوادم LAN خلف نفق HTTPS أو Reverse Proxy محلي.
2. **توافق الترطيب (SSR Hydration):**
   - أي قراءة لـ `localStorage` أو `window` أو `navigator` يجب أن تتم عبر `useSyncExternalStore` أو داخل `useEffect` بعد الـ mount، مع توفير `getServerSnapshot = () => null`.
3. **أمان الاعتمادات وميكروتك:**
   - الكود القديم في `legacy/` كان يحتوي على `adminPin` وحسابات ميكروتك مكشوفة. تم استبعادها تماماً. ذكّر صاحب المشروع بتغيير كلمة مرور راوتر ميكروتك والـ PIN.
